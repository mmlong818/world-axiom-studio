# 万象铸界 · 世界观生成工作台

一个可在本机运行的网页版世界之书生成工具。它接受一句简要说明、已有作品名称、多部参考作品或一本书，既可以创造新世界，也可以依据材料还原已有世界。工作流是“提供依据 → 研究资料 → 选择世界方向 → 建立世界正典并编纂正文 → 发布”，最终输出可查阅的图文 Wiki、三分钟世界概览与结构化 JSON。

世界之书不是设定项清单、风物考据专著，也不是故事开场。正文由六个相互引用的部分组成：一眼看懂这个世界、世界如何运转、地方与彼此关系、历史为何形成今天、人们怎样生活、重要名称与查阅条目。它先帮助读者建立整体认识，再逐步补充细节；最后只保留理解世界不可缺少的少量条目。基础规律通过可观察的事实和生活后果呈现，不适用或没有依据的内容保持未知。游戏、小说和视觉设计只作为下游应用层，不能反过来制造世界事实。

文本生成只使用一套统一的新系统规则，但按任务理解、资料研究、方向设计、正典建立、正文编纂、审计和简版七种职责分阶段工作。每一阶段只做自己的工作；通用世界观框架只用于发现缺口，不会变成必须填满的字段清单。

世界列表是独立的上级页面。只有创建或打开一个世界后，才会进入“依据 → 研究 → 方向 → 世界 → 发布”的五个工作区。

列表只保存用户创建的世界。进行中的世界可以归档；归档后可以恢复，也可以经过二次确认永久删除。为了避免误删，未归档世界不能直接删除。

## 直接运行

需要 Node.js 20 或更新版本。

```powershell
npm install
npm start
```

浏览器打开：`http://127.0.0.1:4277`

启动器会在 Node.js 24 或更高版本中自动接管 `HTTP_PROXY` / `HTTPS_PROXY`，避免网页服务可以启动、但 OpenAI 等模型端点一直连接超时。服务商、模型 ID、端点和 API Key 都保存在当前本地浏览器中，不写入项目文件、世界存档或服务日志；刷新页面后仍可继续使用。

产品只使用真实模型生成。首次使用时在“模型与接口”中选择服务商并填写 API Key；系统会从账号端点读取可用模型，选择后发送一条极短请求测试连接、修正兼容参数，通过后才允许保存启用。创造模式会提供三份具体、可读的世界介绍方向；还原模式会让三张候选共享同一事实底座，只改变介绍重点。

## 真实模型模式

在页面左下角打开“模型与接口”，按顺序完成：

- 连接账号：API 服务填写 Key；Claude CLI 使用本机 Claude Code 登录额度，不复制登录凭证
- 读取模型：API 服务从当前账号和端点实时获取模型列表；Claude CLI 读取完整官方别名、百万上下文入口和本机自定义映射
- 选择并验证：发送一条极短测试请求，确认模型确实可用并自动采用兼容参数
- 保存启用：只有通过测试的配置才能成为生成通道

内置 OpenRouter、Claude CLI、OpenAI、Anthropic、Gemini、DeepSeek、智谱、Kimi、MiniMax、通义千问、豆包、xAI 与自定义兼容端点。OpenRouter 和各厂商会显示账号实际返回的模型；自定义端点支持 OpenAI、Anthropic 或 Gemini 接口标准，也可连接本机模型服务。

API Key 按服务商保存在当前浏览器的本地存储中：不会写入项目文件、世界存档、导出文件或服务日志。可随时在“模型与接口”中清除本机保存的密钥。

## 支持的书籍格式

- PDF（需包含可选中文字）
- EPUB
- DOCX
- TXT、Markdown、HTML

扫描版 PDF 需要先做 OCR。单文件上限 25 MB。程序只向模型发送结构分析所需的采样：开篇与目录附近、均匀分布在全书的八个片段、结尾及规则说明性段落，不会把原书写入本地数据库。

对已有作品，系统会先复现资料能够确认的时空、人物或族群、地点、组织、事件与生活事实，再把资料缺口和用户明确要求作为扩展空间。它不会复制原文表达，也不会把原著专名换名后冒充原创。商业发布前仍应自行核对版权与开放许可条款。

## 生成与导出

1. 输入世界命题、已有作品名称、多部参考作品，或上传一本书。
2. 模型先理解任务；遇到已有作品时，按识别出的准确名称收集故事梗概、原文片段和可核对的公开资料。
3. 资料研究形成可见的故事档案：先说明原作讲了什么，再整理人物与群体、地方风物、民风日常、关键事件、公开来源和资料缺口。
4. 系统根据同一份故事档案提供恰好 3 个约 200 字的呈现方向。方向只说明准备怎样介绍世界，并直接列出要承接的原著地点、人物或族群和事件。多作品融合必须确定主世界、次世界和原著时空接入点；主世界事实优先，次世界保留自身身份后合理进入。
5. 选定方向后先建立世界正典，再分四批编纂正文。正典是所有正文、Wiki、简版和图片共用的唯一事实模型。
6. 审计器分别检查正典矛盾与正文违约，包括自然规律、空间关系、历史因果、制度来源、普通人生计、语言可读性、条目价值和来源边界。
7. 下载：
   - 独立世界之书 Wiki HTML（包含六部分目录、来源层与 3 张离线结构图）
   - 世界概览 Markdown
   - 世界模型与成书结构 JSON

完整世界按四批生成，每完成一批就保存一次。如果模型超时或接口临时失败，页面会显示“从中断处继续”，不会重新生成已经完成的部分。

每批正文保存前还会经过本地完整性检查：必须包含对应的明确章节标题，并达到最低有效内容量。模型返回被截断、只有提纲或缺少章节时，该批不会写入世界档案，用户可以直接从中断处重试。创造和还原模式都必须先识别出有效的输入约束；输入没有进入结果时不会继续生成。

图片模型是可选项。未配置图片模型时，Wiki 会使用与世界种子联动的编辑式结构图；配置后可生成 3 张 AI 配图替换它们。封面图位于世界开头，地方关系图插入“地方与彼此关系”，世界关系图插入“人们怎样生活”，不是把所有图片集中堆在正文前面。图片接口若返回临时网址，服务会尝试下载并转成内嵌数据；下载失败时，独立 Wiki 自动改用本地结构图，保证离线打开不会出现空白图片。

## 验证

```powershell
npm run check
npm test
```

`check` 检查全部 JavaScript 语法；`test` 覆盖书籍采样、四种任务模式、研究档案、三个方向、世界正典、提示边界、提供商配置、导出和世界归档删除边界。测试模型服务不会产生外部费用。

## 项目结构

- `server.mjs`：本地网页服务与 API 边界。
- `lib/extractors.mjs`：PDF、EPUB、DOCX 与纯文本解析、书籍采样。
- `lib/providers.mjs`：多模型协议适配与图片接口。
- `lib/model-routing.mjs`：模型列表发现、真实连接测试与安全配置修正。
- `lib/claude-cli.mjs`：通过本机 Claude Code 登录额度调用 Claude，不读取 OAuth 凭证。

Claude CLI 的短连接测试使用低推理强度；正式世界构建使用中等推理强度、精简系统提示和安全模式。长节点最多等待 15 分钟，传输或超时错误不会被结构修复器原样重复执行，已完成内容会保留在当前世界中。
- `lib/research.mjs`：按模型识别结果收集可核对的公开资料。
- `lib/workflow.mjs`：任务简报、研究档案、方向结果和世界正典的数据契约。
- `lib/prompts.mjs`：研究、方向、正典、正文、审计、修补和世界概览提示。
- `public/`：无构建步骤的网页工作台与导出器。
